01

The game

A hidden shopper already knows what they want. We don't. Each turn we may ask about one attribute and return a ranked list of ten products. The session ends the moment the target appears in that list — or at turn ten.

TechnicalScore = 0.50 · HitRate@10 + 0.30 · MRR + 0.20 · Efficiency Efficiency = clip( (11 − MTTC) / 10 , 0 , 1 ) // a miss counts as turn 11

The simulated shopper is strict: it reads the structured ask_attribute field and ignores our prose entirely. Ask for a colour, get the colour. Ask nothing useful, learn nothing. A session plays out like this.

02

What the evaluator actually revealed

We read the scoring code rather than the brief. Five findings shaped every decision that follows.

Constraints are the product's own words

96.2%

The hidden requirements are lifted verbatim from the target's own feature text. So this is a phrase-matching problem, not a semantic-similarity one — and exact rare phrases are gold.

One question dominates all others

other

The reply filter is attribute == "other" or classify(v) == attribute. The other match set is a superset of every typed attribute's set. That's a dominance proof, not a hunch.

Two attributes carry everything

706 / 800

Across 200 sessions: feature 404, material 302, colour 60, style 19, size 11, use-case 4 — and zero for budget or brand. Asking about budget wastes a turn by construction.

Category is the strongest single signal

8

The opening hands us a category whose bucket holds a median of eight products, out of 1,115 buckets across 50,000 items. Enormous, and free.

Rank is worth ~13× a turn

0.26 vs 0.02

Sessions end at first hit, so surfacing at rank 8 locks in a poor score forever. Moving 8→1 gains 0.26; waiting one extra turn costs 0.02. This inverts the obvious strategy.

Speed is already solved

1.85

The theoretical floor for turns-to-convert. We're at 2.83, and the remaining gap is worth only +0.005 of final score. Stop optimising speed.

03

The move that mattered

Because rank outweighs speed so heavily, the winning behaviour is counter-intuitive: stay quiet when unsure. Withhold recommendations until the candidate pool is genuinely narrow, rather than hitting early at a mediocre rank and locking it in.

How a turn flows

Extraction runs as a cascade so no single layer is load-bearing. If the organiser paraphrases the shopper's replies, the template layer degrades and the salience layer carries the system.

The override subtlety

When the shopper switches intent, the naive fix is to wipe memory. That's wrong — the abandoned preference and the new one both describe the same target product, so a full wipe throws away up to four correct clues. We revoke only the preference stated in the opening and keep everything learned from questions.

06

Where the work happens

The downloaded competition kit stays untouched — it is our source of truth for the evaluator, the contract and the data. All our code lives beside it.

Techjam/ ├── techjam-conversational-search/ ← read-only. never edited. │ ├── evaluator/ official scorer │ ├── data/ 50,000 products · 200 sessions │ └── docs/ API contract · submission rules └── copilot/ ← all our work ├── src/ agent implementation ├── tools/ harness · perturbation · tracing ├── results/ scored runs · ablations └── submission/ built hand-in bundle

This works because the official scorer takes the agent as an argument — evaluate(agent, samples, …). Our harness imports the real evaluator and passes our own agent in, so we get authentic scores without editing a single file of the kit.

07

Build order

Deliberately sequenced: port the validated core first, build measurement before tuning, then spend the remaining effort on robustness rather than chasing points.

  1. Port, don't redesign
    Move the working prototype into a real package. Target: reproduce 0.899 exactly.
  2. Measurement before tuning
    Harness with per-scenario tables, loss attribution and oracle ceilings — so we know whether the next hour belongs to extraction, retrieval or ranking.
  3. Exclude what we already showed
    If the session didn't end, the target wasn't in those ten. Dropping them lifts everything below by ten ranks — provably free.
  4. Fix the scorer
    Log-product coverage instead of a sum, because the requirements are a conjunction. Length-normalise. Prior breaks ties only.
  5. Earn the robustness
    Template-free salience extraction, then prove it: the no-templates run must stay within 0.03.
  6. Adversarial paraphrase
    Five levels, from synonym swaps to removing the sentence carriers entirely. This is the private-set insurance policy.
  7. Optional tiers
    Local embeddings, then external LLM — both strictly additive, both able to vanish without breaking anything.
  8. Package and disclose
    Submission bundle, README, and honest reporting of latency, tokens, cost and network needs.

Statistical discipline

With 200 sessions the noise floor is roughly ±0.03 on hit rate. Every comparison prints a bootstrap confidence interval, and any difference smaller than its interval gets reported as “no measured effect” — never as an improvement.

Scores produced by the unmodified official evaluator on the 200-session public set. 800 sessions are held out privately, which is why robustness — not the public number — drives the plan.
